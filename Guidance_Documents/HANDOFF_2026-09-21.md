### 8a. Two real bugs found and fixed while reading out completed-but-idle runs

Both were the same class of mistake: a script hardcoded the default seat names
(`writer_advocate` / `counterparty` / `neutral_adjudicator`) instead of using the
instrument or community actually passed to it, so an alternate seat naming (the
edges-off cell's `_noedge` suffix) silently returned zero objections instead of raising
an error. Neither affected any previously-registered number; both were caught before
any number was read, by hand-computing the true 2x2 table from the raw votes CSV and
finding it did not match the script's output.

1. **`scripts/analyze_flooding.py`**: `_aita_block` (and its callers `analyse`, `main`)
   hardcoded `AITA` internally even when `build_debates` had correctly used
   `AITA_NOEDGE`. Fixed by threading the instrument through every call site. A
   regression check was added to the selftest: a synthetic panel built under
   `_noedge`-suffixed seats must give the same phi values as the default-seat panel.
   The registered grok cell was re-run before and after the fix and reproduces byte for
   byte (0 leaf differences in a full recursive JSON comparison).
2. **`scripts/verify_pillar3_headline.py`** (my own independent-verification script):
   its diagnostic `n_objectors`-vs-votes cross-check had the same hardcoded-seats bug.
   Purely cosmetic (the actual fired/lift/delta figures read `n_objectors` from the rows
   CSV directly and were never affected), but fixed with a per-community seat table so
   the diagnostic itself is trustworthy.
